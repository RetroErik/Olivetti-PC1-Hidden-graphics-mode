Understanding the CGA "192 Byte Gap" Problem
CGA Video RAM: 16KB (Segment: 0xB800)
Interleaved Memory Layout
Even Lines
Bank 1 (Offset 0x0000)
Line 0 →
Line 2 →
Line 4 →
... (100 even rows × 80 bytes = 8,000 bytes)
Odd Lines
Bank 2 (Offset 0x2000)
← Line 1
← Line 3
← Line 5
... (100 odd rows × 80 bytes = 8,000 bytes)
0x0000
Even lines (8,000 bytes used)
0x1F40
← 192 bytes unused gap
0x2000
Odd lines (8,000 bytes used)
0x3F40
← 192 bytes unused gap
Each 8KB bank = 8,192 bytes total → 8,000 used + 192 unused
The Myth: "192 Byte Gap"
Programmers see a "gap" of
192 bytes between banks

They try to address
"the gap" directly
The Reality: "8,192 Byte Offset"
The bank-to-bank offset is a
fixed hardware constant:
⬇
8,192 Bytes
= 0x2000 hex = 8 KB exactly

An 8,192 byte offset (0x2000) between banks causes a perceived "192 byte gap".

Interleaved Memory forces a big jump between banks. The 192 "gap" bytes are just the unused tail of each 8KB bank.

✅ Corrected Values (vs. original illustration)

The original illustration stated "8,032 bytes" — this was incorrect.
The actual bank offset is 0x2000 = 8,192 bytes (a full 8KB).
Each bank uses 100 rows × 80 bytes = 8,000 bytes, leaving 8,192 − 8,000 = 192 bytes unused at the end.
The erroneous "8,032" likely came from subtracting 160 (pixel count) instead of 80 (byte count per row).
